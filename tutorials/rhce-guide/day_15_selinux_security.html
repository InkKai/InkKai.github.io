DAY 15 RH134 Unit 5

最強防護罩：SELinux 實戰攻略

這是 Red Hat 考試的大魔王。很多人遇到 Permission denied 就會想把 SELinux 關掉。但身為專業工程師，我們要學會駕馭它，而不是逃避它。

1 什麼是 SELinux？

👮 保全與識別證

傳統的權限 (chmod) 是看你是誰 (User)。
SELinux 是看你戴什麼「識別證」(Context)。
即使你是老闆 (Root)，如果你戴的是「清潔工」的識別證，保全 (SELinux) 就不會讓你進入「金庫」，不管你有沒有鑰匙。

核心觀念：Process (程序) 必須要有正確的 Context，才能存取有對應 Context 的 File (檔案)。

2 模式切換：Enforcing vs Permissive

[root@host ~]# getenforce Enforcing # 嚴格模式 (預設)。阻擋違規行為並記錄 Log。 [root@host ~]# setenforce 0 # 切換到 Permissive (寬容模式)。 # 不會阻擋，只會跳出警告 Log。除錯時非常好用！

3 標籤管理：File Context

網頁伺服器 (httpd) 只能讀取貼有 httpd_sys_content_t 標籤的檔案。 如果你自己建了一個網頁，但標籤貼錯了 (例如貼成 admin_home_t)，網頁就會打不開。

[root@host ~]# ls -Z /var/www/html/index.html ... httpd_sys_content_t ... index.html # -Z : 查看 SELinux Context [root@host ~]# restorecon -Rv /var/www/html # 這是考試必殺技！ # restorecon (Restore Context)：把檔案的標籤「恢復」成系統預設的正確標籤。 # -R (Recursive), -v (Verbose)

如果要把非標準目錄 (例如 /web) 設為網頁目錄：

[root@host ~]# semanage fcontext -a -t httpd_sys_content_t "/web(/.*)?" # 在資料庫中「新增 (-a)」規則：/web 底下所有東西都是 httpd_sys_content_t。 [root@host ~]# restorecon -Rv /web # 套用剛剛的設定。

4 功能開關：SELinux Booleans

有時候我們不是要改檔案標籤，而是要開啟程式的某個功能（例如允許 httpd 連到資料庫）。

[root@host ~]# getsebool -a | grep http # 列出所有跟 http 相關的開關。 [root@host ~]# setsebool -P httpd_can_network_connect on # 開啟開關。 # 注意！一定要加 -P (Persistent)，否則重開機就失效了 (考試陷阱)。

🧪 今日實戰 Lab：修復網頁伺服器

  1. 製造問題：
    在 /root 下建立一個檔案 index.html，然後把它 mv 到 /var/www/html/。
    (因為是從 root 家目錄搬過來的，它會帶著 admin_home_t 的錯誤標籤)。
  2. 驗證問題：
    使用 curl localhost 測試，應該會出現 403 Forbidden (權限不足)，因為 SELinux 擋住了。
  3. 修復 (restorecon)：
    使用 restorecon -Rv /var/www/html 修正標籤。
  4. 再次驗證：
    使用 curl localhost，這次應該能成功看到網頁內容。
