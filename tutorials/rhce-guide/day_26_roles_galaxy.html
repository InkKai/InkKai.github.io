大型專案管理：Roles 角色分工

當你的 Playbook 超過 100 行時，就該考慮「重構」了。Role 是 Ansible 管理複雜專案的標準方式，它把工作拆解成獨立、可重複使用的模組。

1 什麼是 Role？

🎬 電影劇組的比喻

一部電影 (Playbook) 包含很多工作：
Tasks 是演員的台詞。
Vars 是角色的名字。
Templates 是道具。
如果把這些全部混在一起，導演會崩潰。
Role 就是把這些東西分門別類放進不同的資料夾 (Tasks 歸 Tasks, Vars 歸 Vars)，變成一個「燈光組包」或「音效組包」。

2 建立 Role：目錄結構

我們不用手動建立一堆資料夾，用指令就好。

[student@control ~]$ cd roles/ # 通常會在專案目錄下建一個 roles 資料夾 [student@control roles]$ ansible-galaxy init my_role # 自動產生標準結構

標準結構說明 (考試重點)：

  • my_role/tasks/main.yml: 主要的執行步驟 (必備)。
  • my_role/handlers/main.yml: 觸發器 (如重啟服務)。
  • my_role/templates/: 放 .j2 模板檔。
  • my_role/files/: 放靜態檔案 (copy 用)。
  • my_role/vars/main.yml: 定義變數 (優先權高)。
  • my_role/defaults/main.yml: 預設變數 (優先權最低，給人覆蓋用)。

3 在 Playbook 中使用 Role

有了 Role 之後，你的 Playbook 會變得超級乾淨。

--- - name: Deploy Web Server hosts: webservers roles: - my_role # 就這樣！一行搞定。 - { role: database, db_port: 3306 } # 也可以傳變數進去

4 Ansible Galaxy

這是 Ansible 的「App Store」。你可以下載別人寫好的 Role。

[student@control ~]$ ansible-galaxy search nginx # 搜尋。 [student@control ~]$ ansible-galaxy install geerlingguy.nginx # 下載並安裝。

5 RHEL System Roles

🔥 考試必考

Red Hat 官方提供了一套高品質的 Roles，用來設定網路、時間、SELinux 等。
套件名稱：rhel-system-roles
安裝位置：/usr/share/ansible/roles/

考試時，你通常不需要從頭寫 Network 或 SELinux 的設定，直接呼叫這些官方 Role 傳參數進去就好。

🧪 今日實戰 Lab：封裝 Apache

  1. 初始化 Role：
    在 ~/ansible-lab/roles 下建立 apache_role。
    ansible-galaxy init apache_role
  2. 搬移 Tasks：
    編輯 roles/apache_role/tasks/main.yml。
    加入安裝 httpd、啟動服務、設定防火牆的 Task。
  3. 搬移 Templates：
    把 index.html.j2 放到 roles/apache_role/templates/。
    在 tasks 裡使用 template 模組 (src 不用寫路徑，直接寫檔名)。
  4. 呼叫 Role：
    建立 site.yml，內容只要呼叫這個 Role。
    執行並驗證。
