容器時代：Podman 基礎與管理

恭喜完成 Phase 2！最後一哩路，我們要學習現代 IT 最火紅的技術——容器。Red Hat 不用 Docker，我們用 Podman。為什麼？因為它不用 Root 也能跑，更安全！

1 容器是什麼？

🍱 便當盒比喻

虛擬機 (VM)：像是一整套行動廚房。不管你要煮什麼，都要把瓦斯爐、流理台、鍋子全部搬過去。很重、很慢。
容器 (Container)：像是做好的便當。廚房（Kernel）用原本電腦的就好，你只要帶食物（App + Library）過去。很輕、秒開。

Podman vs Docker：Podman 是 Daemonless 的，意思是它沒有一個背景長駐的肥大程式，而且支援 Rootless (一般使用者也能跑容器)。

2 基礎指令

指令跟 Docker 幾乎一模一樣。

[student@host ~]$ podman login registry.redhat.io # 登入映像檔倉庫 (Registry)。 [student@host ~]$ podman search httpd # 搜尋 httpd 映像檔。 [student@host ~]$ podman pull registry.access.redhat.com/ubi9/httpd-24 # 下載 (Pull) 映像檔到本地。 [student@host ~]$ podman images # 查看已下載的便當 (Images)。

3 執行容器：Run

[student@host ~]$ podman run -d -p 8080:80 --name myweb ubi9/httpd-24 # -d: Detach (背景執行)。 # -p 8080:80: 埠口對應。把外面的 8080 對應到便當裡的 80。 # --name: 幫容器取個名字 (不然會是亂碼)。
[student@host ~]$ podman ps # 查看正在跑的容器。 [student@host ~]$ podman stop myweb # 停止容器。

4 整合 Systemd (考試重點)

Podman 容器重開機後會消失。為了讓它像一般服務一樣開機自啟，我們需要 systemd 幫忙。

🔥 必考步驟

  1. 先手動跑起來容器 (podman run ...)。
  2. 建立 systemd 設定檔目錄：mkdir -p ~/.config/systemd/user/
  3. 產生設定檔：
    podman generate systemd --name myweb --files --new
  4. 重新載入：systemctl --user daemon-reload
  5. 啟用服務：systemctl --user enable --now container-myweb.service
  6. 啟用使用者滯留 (Lingering)： 讓使用者登出後服務繼續跑。
    loginctl enable-linger student

🧪 今日實戰 Lab：容器服務化

  1. 準備容器：
    使用 httpd 映像檔，建立一個名為 web-server 的容器，Port 對應 8080:80。
  2. 產生 Service 檔：
    使用 podman generate systemd 產生 container-web-server.service。
  3. 設定開機自啟：
    將 service 檔放入 ~/.config/systemd/user/。
    執行 systemctl --user enable --now container-web-server.service。
  4. 驗證：
    重開機，登入後檢查 podman ps，確認容器有自動跑起來。
