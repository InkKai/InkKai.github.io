變數的魔力：Variables 與 Facts

如果 Playbook 是劇本，變數就是「填空題」。透過變數，我們可以寫一份劇本，然後應用在一百種不同的環境，讓自動化真正變得靈活。

1 為什麼需要變數？

📝 表單的比喻

想像你要寫信給 100 個人。你不會手寫 100 封信。 你會寫一封「範本」：
親愛的 {{ name }}，祝你 {{ event }} 快樂！
然後準備一份名單（變數檔）。Ansible 執行時，會自動把 {{ name }} 換成真正的人名。

2 定義與使用變數

使用 {{ variable_name }} 來引用變數。

--- - name: Install Package hosts: all vars: web_pkg: httpd # 定義變數 tasks: - name: Install the package ansible.builtin.dnf: name: "{{ web_pkg }}" # 使用變數 (注意要加引號！) state: present

🔥 考試地雷

如果變數是該行的第一個字，一定要用雙引號 "{{ var }}" 包起來，不然 YAML 解析器會報錯。

3 自動變數：Ansible Facts

每次 Playbook 執行時，第一步通常是 Gathering Facts。這時候 Ansible 會去受控端做「身家調查」，收集 IP、OS 版本、CPU 數量等資訊。

[student@control ~]$ ansible localhost -m setup # 查看收集到的所有 Facts (內容超多)。

常用 Magic Variables：

  • ansible_hostname: 主機名稱 (短)
  • ansible_default_ipv4.address: IP 位址
  • ansible_distribution: OS 發行版 (e.g. RedHat)

4 機密保護：Ansible Vault

密碼、金鑰不能明文寫在 Playbook 裡！用 Vault 加密。

[student@control ~]$ ansible-vault create secret.yml # 建立加密檔案 (會叫你設密碼)。 [student@control ~]$ ansible-vault view secret.yml # 查看內容 (需要輸入密碼)。 [student@control ~]$ ansible-playbook site.yml --ask-vault-pass # 執行時，告訴 Ansible 這裡面有加密檔案，請來問我密碼。

🧪 今日實戰 Lab：動態網頁

  1. 建立變數檔：
    建立 vars.yml，定義 web_content: "Hello from Ansible"。
  2. 撰寫 Playbook：
    建立 web_setup.yml。
    1. 引入 vars_files: ["vars.yml"]。
    2. 安裝 httpd。
    3. 使用 copy 模組，將 content: "{{ web_content }} running on {{ ansible_hostname }}" 寫入 /var/www/html/index.html。
  3. 執行與驗證：
    執行劇本。
    用 curl 測試，你應該會看到網頁內容包含該主機的名字 (Facts)。
