邏輯控制：迴圈、條件與處理器

Playbook 如果只能從上到下跑一遍，那太笨了。我們需要它能「重複做事」(Loop)，能「看情況做事」(When)，還要在「有改變時才做事」(Handler)。這就是程式邏輯。

1 迴圈：Loop

想要安裝 5 個軟體，不需要寫 5 個 Task。用 loop 只要寫一個。
Ansible 會把 {{ item }} 這個變數自動替換成列表中的項目。

- name: Install multiple packages ansible.builtin.dnf: name: "{{ item }}" # 神奇變數 item state: present loop: - httpd - vim - git

2 條件判斷：When

如果這個是 RedHat 系統，我就裝 rpm；如果是 Ubuntu，我就裝 deb。 when 讓我們可以根據 Facts (身家調查) 來決定要不要執行 Task。

- name: Install httpd only on RedHat ansible.builtin.dnf: name: httpd state: present when: ansible_distribution == "RedHat"

3 觸發器：Handlers

🔔 服務鈴的比喻

當你修改了設定檔 (Config)，必須重啟服務 (Restart) 才會生效。
但是，如果設定檔沒有改變，就不需要重啟（浪費時間）。
Handler 就是那個「只在設定檔有變時」才會被按下的服務鈴。

tasks: - name: Copy config file ansible.builtin.copy: src: httpd.conf dest: /etc/httpd/conf/httpd.conf notify: Restart Httpd # 如果 Copy 有改變 (Changed)，就去按鈴。 handlers: - name: Restart Httpd # 這裡的名字要跟 notify 一模一樣！ ansible.builtin.service: name: httpd state: restarted

🧪 今日實戰 Lab：智慧安裝

  1. 批量安裝：
    使用 loop 安裝 mariadb-server, php, wget 三個套件。
  2. 條件啟動：
    使用 when 判斷：如果安裝成功 (mariadb-server 存在)，才啟動 mariadb 服務。
  3. 設定與重啟：
    建立一個 dummy 設定檔 /tmp/my.cnf。
    設定 notify，當該檔案內容改變時，觸發 Handler 重新啟動 mariadb。
  4. 驗證：
    執行第一次 (應該會重啟)。
    執行第二次 (因為設定檔沒變，Handler 不會跑，服務不會重啟 -> 冪等性)。
