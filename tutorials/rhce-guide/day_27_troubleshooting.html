進階技巧：錯誤處理與除錯

自動化最怕「一粒老鼠屎壞了一鍋粥」。只要有一台主機報錯，預設情況下整個劇本可能會停止。今天我們要學習如何讓劇本變得「強韌」，即使跌倒了也能爬起來繼續跑，或者執行 B 計畫。

1 忽略錯誤：Ignore Errors

有時候指令失敗是預期中的（例如檢查某個檔案是否存在，不存在會報錯，但我們不想因此停下來）。

- name: Check if file exists ansible.builtin.command: ls /tmp/missing_file ignore_errors: yes # 即使找不到檔案 (Return Code != 0)，Ansible 也會顯示紅色錯誤，但會繼續執行下一個 Task。

2 救援機制：Block, Rescue, Always

⛑️ 消防演習的比喻

Block：正常要做的事（嘗試升級資料庫）。
Rescue：如果 Block 失敗了（升級失敗），要執行的補救措施（還原備份）。
Always：不管成功或失敗，最後都要做的事（重啟服務）。

- name: Upgrade Transaction block: - name: Upgrade DB ansible.builtin.shell: /usr/local/bin/upgrade.sh rescue: - name: Restore DB ansible.builtin.shell: /usr/local/bin/restore.sh always: - name: Cleanup temp files ansible.builtin.file: path: /tmp/upgrade.log state: absent

3 自訂成敗：Failed_when & Changed_when

有時候 Ansible 判斷的成功失敗不是我們要的。

- name: Run script ansible.builtin.command: /usr/local/bin/check_status.sh register: result failed_when: "'CRITICAL' in result.stdout" # 只有當輸出包含 "CRITICAL" 字眼時，才算失敗。其他錯誤代碼都算成功。 - name: Check date ansible.builtin.command: date changed_when: false # 告訴 Ansible：這個指令只是檢查用的，沒有修改系統，請顯示「綠色 (OK)」而不是「黃色 (Changed)」。

4 除錯神器：Debug 模組

變數抓不到？條件判斷錯誤？用 debug 把變數印出來看看。

- name: Print variable ansible.builtin.debug: msg: "The hostname is {{ ansible_hostname }} and result is {{ result.stdout }}" verbosity: 1 # verbosity: 1 代表只有在執行時加 -v 才會顯示這個 debug 訊息。

🧪 今日實戰 Lab：強韌的升級劇本

  1. 模擬失敗：
    撰寫一個 Playbook，嘗試安裝一個不存在的套件 (例如 package_not_exist)。
  2. 加入 Rescue：
    使用 block 包住安裝任務。
    在 rescue 區塊中，寫一個 Task 印出 "Install failed, attempting fallback..." (使用 debug 模組)。
  3. 加入 Always：
    在 always 區塊中，寫一個 Task 印出 "Upgrade process finished"。
  4. 執行：
    執行劇本，觀察它是否雖然安裝失敗，但仍然執行了 Rescue 和 Always 的任務，且最後顯示 Playbook 執行成功 (因為 Rescue 救回來了)。
