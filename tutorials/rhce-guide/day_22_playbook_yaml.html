劇本第一章：Playbook 與 YAML

Ad-Hoc 雖然方便，但不能重複使用。如果要管理複雜的伺服器，我們需要「劇本 (Playbook)」。今天我們要挑戰新手最容易卡關的大魔王——YAML 縮排。

1 YAML 語法：縮排就是生命

📜 大綱筆記的比喻

YAML 就像我們寫筆記的縮排大綱：
1. 第一層
  1.1 第二層 (前面空兩格)
  1.2 第二層
規則：
1. 絕對不能用 Tab 鍵！ 只能用空白鍵 (Space)。
2. 每一層縮排通常是 2 個空白鍵。
3. 列表 (List) 用 - 開頭。
4. 鍵值對 (Key-Value) 用 : 分隔。

2 Playbook 解剖學

一個 Playbook (`.yml`) 包含一個或多個 Play (劇目)，每個 Play 包含多個 Task (任務)。

--- - name: Configure Web Server # Play 的名稱 hosts: webservers # 對象：這齣戲要演給誰看？ tasks: - name: Install httpd # Task 1: 安裝 ansible.builtin.dnf: # 使用 dnf 模組 name: httpd state: present - name: Start service # Task 2: 啟動 ansible.builtin.service: # 使用 service 模組 name: httpd state: started enabled: true

3 冪等性 (Idempotency)

這是 Ansible 的靈魂。
如果你執行上面的劇本 100 次：
第 1 次：Ansible 會安裝 httpd 並啟動它 (Changed)。
第 2~100 次：Ansible 會檢查發現已經裝好且啟動了，所以什麼都不做 (OK)。
結果永遠保證是一樣的。

4 執行劇本

寫好檔案 (例如 web.yml) 後，怎麼跑？

1. 語法檢查 (Syntax Check)

[student@control ~]$ ansible-playbook --syntax-check web.yml # 沒消息就是好消息。如果有錯，它會告訴你在第幾行。

2. 正式執行

[student@control ~]$ ansible-playbook web.yml

3. 模擬執行 (Dry Run)

[student@control ~]$ ansible-playbook -C web.yml # -C (Check): 假裝跑一次，告訴你會改變什麼，但不會真的動手。
