系統的脈搏：行程管理與監控

電腦變慢了？程式當機了關不掉？這時候你就需要當「系統醫生」，學會把脈（監控 Process）和進行急救手術（Kill）。

1 什麼是 Process？

👨‍🍳 餐廳訂單的比喻

程式 (Program)：就像「食譜」。它是硬碟裡死板板的檔案（例如 /usr/bin/vim）。
程序 (Process)：就像「正在做的料理」。當你執行程式，CPU 開始運算，它就變成了 Process。每個 Process 都有一個獨一無二的編號，叫做 PID (Process ID)，就像訂單編號。

2 靜態監控：ps (Process Status)

這是拍快照。它只顯示「執行指令當下」的狀態。

[student@host ~]$ ps aux # a: 顯示所有使用者的程序 # u: 顯示使用者的詳細資訊 (CPU%, MEM%) # x: 顯示沒有控制終端機的程序 (背景服務)

或者你也可以用 Red Hat 推薦的格式：

[student@host ~]$ ps -ef # -e: Every process (所有程序) # -f: Full format (完整格式，包含 PPID 父程序 ID)

3 動態監控：top

這是直播。畫面會每 3 秒更新一次，讓你知道現在誰佔用了 CPU。

[student@host ~]$ top

Top 裡的快捷鍵 (進去後按)：

  • P：按 CPU 使用率排序 (預設)。
  • M：按 Memory 使用率排序 (抓出吃記憶體的怪獸)。
  • k：輸入 PID 來砍掉某個程序。
  • q：離開。

4 終止程序：kill

當程式當機時，我們需要發送「信號 (Signal)」給它。

信號代碼 名稱 意義
15 SIGTERM 溫柔勸退 (預設)。請程式自己收拾好東西（存檔）然後關閉。
9 SIGKILL 強制獵殺。直接把程式從記憶體移除，不管它有沒有存檔。非必要別用。
[student@host ~]$ kill 1234 # 傳送 SIGTERM 給 PID 1234 [student@host ~]$ kill -9 1234 # 強制殺死 PID 1234

5 系統日記：Logs

系統發生什麼事都會寫在日記裡。RHEL 有兩個主要看日誌的地方。

1. 傳統日誌檔 (/var/log)

  • /var/log/messages：大部分系統訊息。
  • /var/log/secure：安全性相關（誰登入失敗、誰用了 sudo）。

2. 新式日誌系統：journalctl

[student@host ~]$ journalctl -n 5 # 看最新的 5 條日誌 [student@host ~]$ journalctl -p err # 只看「錯誤 (Error)」等級以上的嚴重訊息 [student@host ~]$ journalctl -f # Follow (追蹤)：像直播一樣，有新日誌會馬上跳出來 (按 Ctrl+C 離開)

🧪 今日實戰 Lab：獵殺睡美人

  1. 製造背景程序：
    執行一個會睡覺 1000 秒的指令，並丟到背景執行 (&)。
    sleep 1000 &
  2. 找出 PID：
    使用 ps 找出剛剛那個 sleep 指令的 PID。
    ps aux | grep sleep
  3. 執行獵殺：
    使用 kill 指令終止該 PID。
    kill [PID]
  4. 調查日誌：
    查看最近誰使用了 sudo 指令。
    journalctl /usr/bin/sudo
